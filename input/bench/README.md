# Benchmark inputs (`scripts/bench_engines.py`, `scripts/bench_retrieval.py`)

Each benchmark is a work-dir template laid out exactly like the API's run
directories (`api/infrastructure/cli/book_command.py`):

```
<name>/
  book_input.txt          the spec the engine reads with -i
  bench.json              how the benchmark drives it (outline mode, output format)
  questions.json          retrieval evaluation sets (per language) for bench_retrieval.py
  kb/<source_id>/<file>   the knowledge base, one directory per source (as --kb-dir)
```

| Name | Spec | Outline | KB |
|---|---|---|---|
| `cs_book` | the existing Czech book `input/book/book_input.txt` (explicit `##` outline, 79 pages) | from the TXT outline (`--use-txt`) | two English sources: a Markdown guide on generative AI in teaching and a PDF on assessment and academic integrity |
| `en_book` | new English TXT-only spec (12 pages, no outline) | generated by the LLM (`--use-txt`) | two English sources: a Markdown text on mechanical computing and a PDF on the stored-program computer |

The Czech book against English sources is the project's main real use and the
reason for the cross-lingual retrieval sets (`questions.json` → `sets.cs`).

## Licence

All four KB documents were written for this benchmark and are released under
the repository's Apache 2.0 licence. The PDFs are built from the LaTeX sources
in `_sources/` (`lualatex <file>.tex`, twice); their running header and page
footer are deliberate, so the new extractor's header/footer removal is
exercised. The question sets were hand-written against these texts; each
question is anchored to a verbatim answer span.
