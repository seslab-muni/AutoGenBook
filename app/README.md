# AutoGenBook Studio (frontend)

Vite + React 19 (strict TypeScript) frontend for AutoGenBook, on TanStack Router,
TanStack Query, Zustand, and shadcn/ui on Tailwind 4. It talks to the FastAPI
service in `../api/` and is served by nginx in the Docker Compose stack (see the
root `CLAUDE.md`).

This is currently a scaffold: routing, data-layer, and design-system plumbing
are wired up, but there are no real screens yet (those land in #16 onward).
`app/_reference/` holds the previous AI-Studio-exported mock UI, kept for one
release purely as a layout/styling reference for later issues; it is excluded
from `tsc`, ESLint, Vitest and the Docker image, and will be deleted in #23 —
don't add new code there.

## Prerequisites

- Node.js 22+ (Docker builds on `node:22-alpine`; also verified on Node 26)
- pnpm 11 (`corepack enable` will pick up the pinned version from
  `package.json`'s `packageManager` field)

## Scripts

```bash
pnpm install        # install dependencies
pnpm dev             # start the Vite dev server on :3000
pnpm lint            # eslint + tsc --noEmit
pnpm format          # prettier --write .
pnpm format:check    # prettier --check .
pnpm test            # vitest (watch mode)
pnpm test:ci         # vitest run (single pass, for CI)
pnpm build           # tsc -b && vite build -> dist/
pnpm preview         # preview the production build locally
```

## Environment / proxying

Copy `.env.example` to `.env` to override the defaults:

- `VITE_API_BASE_URL` — base URL the frontend uses for API calls (default `/api/v1`,
  typed in `src/vite-env.d.ts`).
- `VITE_API_PROXY_TARGET` — target for the Vite dev-server's `/api/*` proxy
  (`vite.config.ts`), so `pnpm dev` can talk to a locally running `api/` service.
  Defaults to `http://localhost:8080`. In the Docker Compose stack, nginx
  (`nginx.conf`) proxies `/api/` to the `api` container instead.

## Folder layout

```
src/
  app/          # providers (QueryClientProvider, RouterProvider) and the router/query-client setup
  routes/       # TanStack Router file-based routes only — thin, no business logic
  features/     # one folder per feature area (components, hooks, queries):
                #   projects, sources, outline, editor, runs, exports
  api/          # typed API client / generated request hooks (#15)
  stores/       # Zustand stores — one small, focused store per concern
  components/
    ui/         # shadcn/ui primitives, generated by `pnpm dlx shadcn add ...` — don't hand-edit
  components/   # shared, hand-written components (not feature- or route-specific)
  lib/          # framework-agnostic helpers (e.g. `cn()` in lib/utils.ts)
  test/         # Vitest setup (`test/setup.ts`) and shared test utilities
  mocks/        # MSW request handlers + fixtures for tests/dev
  routeTree.gen.ts   # generated by @tanstack/router-plugin — committed, don't hand-edit
```

Routes stay thin: a route module owns params/search-param parsing, loader
wiring, and rendering a feature's top-level component — the actual UI and data
logic live under `src/features/<name>`.

## shadcn/ui workflow

`components.json` points the `shadcn` CLI at this project (`new-york` style,
`slate` base color, CSS variables, `@/*` → `src/*`). To add a component:

```bash
pnpm dlx shadcn@latest add <component>
```

This drops the component into `src/components/ui/` using the `cn()` helper
from `src/lib/utils.ts` (not the generated `cn` import some CLI versions default
to — components are patched to `import { cn } from "@/lib/utils"` so there is a
single, hand-maintained implementation). Generated files under
`src/components/ui/` are excluded from ESLint (`eslint.config.js`) since they're
vendor code refreshed by the CLI, not hand-edited.

Known caveat: a handful of Radix-based components (`context-menu`,
`dropdown-menu`, `slider`, `sonner`) currently fail `tsc` under this project's
`exactOptionalPropertyTypes: true` the moment something actually imports them,
because some Radix prop types aren't `exactOptionalPropertyTypes`-clean. This
scaffold doesn't wire any UI together yet so it isn't hit; when a later issue
first imports one of those components, patch the failing prop passthrough to
avoid passing an explicit `undefined` for an optional prop (e.g.
`{...(value !== undefined ? { value } : {})}` instead of `value={value}`).

## Design tokens

`src/index.css` maps the AutoGenBook palette (indigo primary, slate neutrals,
emerald/amber/sky/rose semantic colors) onto shadcn's CSS-variable tokens, adds
`--font-sans` (Plus Jakarta Sans), `--font-serif` (STIX Two Text / Crimson Pro,
for manuscript content), and `--font-mono` (JetBrains Mono) as Tailwind
`@theme` entries, and self-hosts all four via `@fontsource-variable/*` packages
(no Google Fonts `<link>`). Dark mode uses Tailwind 4's `class` variant
(`.dark` on an ancestor) with a full token set already defined in
`src/index.css` — there's no toggle UI yet (#16 adds it).

## Testing

Vitest + `@testing-library/react`, `jsdom` environment, setup in
`src/test/setup.ts`. `src/test/smoke.test.tsx` renders the root route tree
inside a memory-history router to check the provider stack, router, and
placeholder routes all mount correctly.
